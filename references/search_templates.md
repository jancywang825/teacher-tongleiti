# 相似题检索策略与检索词模板

本文件用于 Step 3「检索相似题」。核心原则：**按"知识点 + 方法 + 题型 + 学段"检索，优先找"同知识点或同方法"的题，而非原题本身**。学科网、菁优网均为登录墙站点。**发起新题原创需求时，先用已固化 profile 做只读登录态预检（第 0 步 0-A）：任一站有效则直接复用、不弹窗不扫码；两站均失效/从未登录/无法确认，才由用户在 Step 3.0 弹窗中三选一**（菁优网 / 学科网 / WebSearch）：选站点则扫码登录后做站内检索，选 WebSearch 则不登录直接走第 2 级。**预检未命中、用户未选择前不得发起任何检索、不得启动浏览器做站内检索。**

## 一、构造检索词（通用模板）
在检索前，先用 Step 2 得到的标签，拼出 2~3 组检索词。模板：

```
[学段] + [学科] + [知识点模块] + [方法] + [题型]
例：高中 + 数学 + 导数单调性 + 分类讨论 + 解答题
例：初中 + 物理 + 浮力 + 受力分析 + 计算题
```

补充检索（找变式灵感）：
```
[知识点] + 变式题 / 改编题 / 经典题
[方法] + 例题
```

## 二、溯源通道选择与检索执行顺序

### 第 0 步：登录态预检 → 溯源通道选择（需求 2.9.2 / 2.9.3，硬约束）

#### 0-A. 登录态预检（2.9.3，先做，只读）
> 发起**新题原创需求**时，Step 1 识别、Step 2 打标签完成后，**先做只读预检**：用已固化 profile 无头打开站点首页，读登录标志。**不检索、不抓题、不提交表单、不展示二维码。**
> **跳过预检的两种情形**：① 用户明确说「本次用 WebSearch / 不登录」→ 直接走 0-B 的 C；② 同批次「处理队列」重跑 → 沿用批次已定通道，不重复预检。

| 站点 | 预检命令（只读） | 有效标志 |
|---|---|---|
| 菁优网 | `agent-browser --profile ~/.workbuddy/jyeoo-profile open "https://www.jyeoo.com/" --args "--no-sandbox"` | 页面含「个人中心 / 会员 / 用户名 / 退出」，且无「登录 / 注册」 |
| 学科网 | `agent-browser --profile ~/.workbuddy/zxxk-profile open "https://www.zxxk.com/" --args "--no-sandbox"` | 右上角显示用户名（如 `xkw_xxx`）或「学校会员」，且无「登录 / 立即登录」 |

- **判定为有效** → **直接复用**：**不弹 0-B 三选一、不弹二维码**，告知「检测到 XX 网登录态有效，已直接复用；如需改用 WebSearch 或另一站点请直接说」，随后直接按第 1.5 级 B 节做站内检索。
- **两站都有效** → 优先**上次使用/最近一次成功登录**的站点；**仅一站有效** → 直接用该站。
- **失效**（跳 `sso.<site>` 登录页 / 出现登录注册 / 二维码 / 验证码 / 401）或**无法确认**（网络失败、WAF 阻断、页面结构变更读不到标志）→ 才执行 0-B；"无法确认"须如实说成"无法确认（网络/风控原因）"，**不得**说成"登录已失效"。
- 预检是「未选择前不得启动浏览器」的唯一例外，且**仅限只读读取登录标志**。

#### 0-B. 三选一弹窗（仅在 0-A 预检未命中时执行）
> 两站均失效 / 从未登录 / 无法确认时，Step 1 识别、Step 2 打标签完成后、**任何检索动作之前**，必须用 `AskUserQuestion` 弹窗让用户三选一（单选、互斥）：

| 选项 | 标签 | 说明 |
|---|---|---|
| A | **菁优网** | 扫码登录后做菁优网站内检索（解析完整） |
| B | **学科网** | 扫码登录后做学科网站内检索（资料/试卷覆盖广） |
| C | **WebSearch** | 不登录，直接用公开网络检索（最快） |

- **未选择前禁止**：发起检索请求、启动浏览器做站内检索、展示二维码（0-A 只读预检除外）。
- 选 **A / B** → 进入「第 1.5 级 A 节：二维码扫码登录」，**紧接着弹窗展示对应站点的登录二维码**；若该站 profile 已登录则跳过二维码并告知用户（正常不会走到这里，0-A 预检命中时已直接复用）。选 A 用 `~/.workbuddy/jyeoo-profile`，选 B 用 `~/.workbuddy/zxxk-profile`，**不得串用**。
- 选 **C** → **跳过第 1 级与第 1.5 级**，直接执行第 2 级 WebSearch（第 3 级兜底保留）；溯源节写明「本次按用户选择采用 Web 公开检索，未执行题库站点站内检索」。
- 选择结果贯穿本批任务（含「处理队列」重跑），同批次不重复弹窗；用户中途要求换通道时按新选择切换并更新溯源节。

### 第 1 级：直连学科网 / 菁优网公开页（WebFetch，仅站点通道）
- 学科网搜索入口示例：`https://www.zxxk.com/search/?q=<URL编码的检索词>`（**实测 2026-10：该 URL 返回 404，学科网检索基本不可用，可跳过直接进入第 1.5 级**）
- 菁优网搜索入口示例：`https://www.jyeoo.com/search?q=<检索词>`（**实测 2026-10：未登录会被重定向回首页，拿不到检索结果**；菁优网按学科有试题检索页如 `https://www.jyeoo.com/math2/ques/search`，但同样需登录）
- 操作：用 WebFetch 访问搜索结果页，提取题面摘要、知识点、难度。
- **若返回登录墙/空页/反爬提示/404** → 进入第 1.5 级（引导用户登录目标题库站点），不要反复重试。

### 第 1.5 级：引导用户登录目标题库站点（菁优网 / 学科网，流程完全一致）
> **进入本级前须已完成第 0 步预检（2.9.3）**：预检命中有效登录态时**直接复用、免扫码**，跳过 A 节登录引导、直接做 B 节站内检索；仅 0-A 未命中且用户在 0-B 选定站点时，才走 A 节扫码。
> 本 Skill 支持两个高质量题库站点：**菁优网（jyeoo）** 与 **学科网（zxxk）**。**用哪个由 0-A 预检结果或 0-B 用户选择决定**（选哪个就只登哪个，不擅自更换、不两站并登）。**两站登录与站内检索流程完全一致**：持久化 profile、登录一次永久复用、凭据安全红线相同。
> 下面以菁优网为例写清每一步；**学科网照搬同样步骤**，仅三处不同：profile 路径改为 `~/.workbuddy/zxxk-profile`、入口改为 `https://www.zxxk.com/`（登录后使用站内搜索框，公开搜索 URL 实测 404 但登录后站内检索可用）、搜索框选择器按其实际 `name`/id 调整（清空步骤见"搜索框是追加"小节）。
> 遇登录墙时**不要默默跳过**，应主动向用户提供登录引导。用户拒绝（无任何站点账号）则进入第 2 级。
> **核心改造（2026-10 起，解决"登录失败率 90%+"）：改用持久化 Chrome 配置文件，登录一次、永久复用，日常检索可无头运行，彻底告别每次重登与窗口丢失。**

**A. 登录引导 —— 【标准流程：二维码扫码登录】（2026-10-21 固化，强制）**
> ⚠️ **【标准流程 · 强制】无论引导用户登录菁优网还是学科网，统一采用「沙箱内无头浏览器生成登录二维码 → 用户扫码确认 → 我获取并持久化登录态」的方式。** 此方式对**密码登录用户**和**扫码登录用户**都适用——沙箱自己生成二维码，用户无需向我们提供账号密码（扫码场景密码甚至不进沙箱浏览器）。在检索之前、检测到目标站点未登录时，主动启动此流程。

**环境前提与为何不用其他方式（实测，务必先看）**：
- ❌ **有头手动登录（`AGENT_BROWSER_HEADED=true`）不可用**：WorkBuddy 沙箱内 Chrome 会因 crashpad Mach 端口握手失败而"打开即崩"（exit early），加 `--no-sandbox`/`--disable-crash-reporter`/`MallocNanoZone=0` 等均无效。**不要再用有头窗口让用户输密码。**
- ❌ **从本机 Chrome 带 `--remote-debugging-port=9222` 导入会话不可用**：沙箱与宿主机的 localhost **网络隔离**——沙箱侧 `curl 127.0.0.1:9222` 与 `agent-browser connect 9222` 均为 connection refused（之前偶发的 502 只是沙箱代理瞎转发，非真连通）。本机 Chrome 即便开了调试端口，沙箱也读不到。**不要再用 debug-port 导入。**
- ✅ **唯一可靠路径**：在沙箱内**无头** Chrome（`--profile` + `--no-sandbox`，**不加** `AGENT_BROWSER_HEADED`）打开目标站点登录页，由沙箱**自己**渲染并生成登录二维码，导出给用户扫。

**标准流程步骤（二维码扫码登录）**：
1. **开无头 Chrome + profile 进登录页**（两站各自独立 profile）：
   - 菁优网：`agent-browser --profile ~/.workbuddy/jyeoo-profile open "https://www.jyeoo.com/math/" --args "--no-sandbox"`（首页 CDP 常抓空白，改开子页更稳；或直抵登录页）。
   - 学科网：`agent-browser --profile ~/.workbuddy/zxxk-profile open "https://www.zxxk.com/" --args "--no-sandbox"` → 进登录页 `https://sso.zxxk.com/login?service=...`（注意：学科网组卷网 `zujuan.xkw.com/quessearch` 被 WAF 直跳/点击都拦，站内检索改走 `search.zxxk.com/doc` 资料搜索 + 选「高中/试卷」筛选，见 B 节）。
   - 若 `open` 后上下文空白，用 `agent-browser eval "window.location.href='<登录页URL>';"` 强制导航（沙箱内此方式稳定）。
2. **定位二维码元素并导出 PNG**（通常是 `<canvas>`，由 JS 绘制；少数站为 `<img>`）：
   ```bash
   agent-browser eval "(()=>{ const cs=[...document.querySelectorAll('canvas')]; const qr=cs.find(c=>c.width>=100&&c.height>=100)||cs[0]; if(!qr) return {err:'no canvas'}; return {dataUrl:qr.toDataURL('image/png'), w:qr.width, h:qr.height}; })()"
   ```
   若返回 `dataUrl`，用 Python 把 base64 解码为 PNG（存工作区临时目录如 `.tmp_<site>/<site>_login_qr.png`，**勿进交付物**）；若返回 `err` 或只有 `<img>`，改用该 `img.src` 下载。
3. **把二维码 PNG 展示给用户**：用 `present_files` 展示上一步的 PNG，并提示「请用 XXX 网 App 或微信扫码，手机上点确认登录」。说明：此二维码只在沙箱会话内登录，不会影响用户本机已有的该站登录态。
4. **等待用户扫码确认**：用户回复「已登录 / 已扫」后，验证登录态——`agent-browser eval` 检查页面出现「个人中心 / 会员 / 学校会员 / 用户名」等、无「登录 / 注册」链接；菁优网/学科网首页均会显示会员态。
5. **持久化登录态**：
   - 浏览器 profile 目录（`~/.workbuddy/<site>-profile`）已留存 cookie/IndexedDB，重开即已登录；
   - 另存一份可移植快照：`agent-browser --profile ~/.workbuddy/<site>-profile state save ~/.workbuddy/<site>-auth.json`（仅存 `~/.workbuddy/`，**不得纳入题目交付物**）。
6. **二维码时效**：通常 1~2 分钟，过期则重生成一张（用户回复「过期」即重跑 2~5 步）。

**凭据安全红线（与标准流程一致）**：账号密码只进用户本机（扫码场景甚至不进沙箱浏览器）；严禁写入 Skill、references、记忆、日志或任何文件。`<site>-auth.json` 与 profile 仅存于 `~/.workbuddy/`（两站凭据同等保护），等同"本机保持登录"。

> 📌 **已废弃 / 不可用的登录方式（明确标记，勿再尝试，避免重复踩坑）**：
> - ❌ **有头手动登录（`AGENT_BROWSER_HEADED=true` + 用户在弹出窗口输密码）**：WorkBuddy 沙箱内 Chrome 必崩，窗口打开即关，无法完成登录。
> - ❌ **从本机 Chrome 带 `--remote-debugging-port=9222` 导出 cookie 注入 profile（"零手动登录"）**：沙箱与宿主机 localhost 网络隔离，沙箱侧连不上本机 9222 端口；之前偶发 502 系沙箱代理误转发，非真连通。此路径在 WorkBuddy 环境下不成立。

**B. 登录后的站内检索（以菁优网为例，学科网同理）：**
- **检索阶段可无头运行**（已登录的 profile 不需要可见窗口）：`agent-browser --profile ~/.workbuddy/jyeoo-profile open "<搜索页>" --args "--no-sandbox"`（学科网换成 zxxk-profile；不加 `AGENT_BROWSER_HEADED`，无声无息完成检索）。
- 直接访问搜索 URL、点导航链接通常**不跳转**；有效路径：首页搜索框 `fill` 关键词 → 点旁边**搜索按钮**提交 → 进入 `math2/ques/search` 结果页（学科网则用登录后站内搜索框提交，进入其检索结果页）。
- **搜索框是追加不是替换（实测坑）**：`agent-browser type` 对 jyeoo 搜索框会把新词**拼接到旧词后**（如"三棱锥…四棱锥…"），导致检索词污染。连续检索前先用 JS 清空：`agent-browser eval "var i=document.querySelector('input[name=qb]'); i.value=''; i.dispatchEvent(new Event('input',{bubbles:true})); 'ok'"`，再 type 新关键词。**学科网的搜索框 name/id 不同，先用 `agent-browser eval "document.querySelector('input[type=search],input[name*=search],input[name*=q]')?.name"` 探明选择器再清空**，逻辑相同。
- 结果页读取：`agent-browser snapshot` 后用 `sed -n 'A,Bp'` 分段读 listitem（每题一个 listitem，含出处链接、题干、难度、组卷/引用数）；`deletion` 标签内是命中关键词的高亮，正文以 StaticText 拼接。结果总数看"共 N 条信息"。
- 结果页左侧有**知识点筛选项**（如「由一元二次不等式的解求参数」，并显示题量），点击进入可拿到该知识点下全部同源题列表——这是找"不同框架同源题"的最佳入口。
- 收集素材时重点找**框架不同**的题（如"解集恰含 N 个整数""解集宽度/根的分布""绝对值+二次"），而不是仅换数字的题。

**C. 用毕清理（按需，非必须）：**
- 默认**保留 profile 登录态**，下次生成直接复用，不再登录（这正是改造目的）。
- 仅当用户明确要求"退出登录"时：在对应站点页面点退出 → `agent-browser --profile ~/.workbuddy/jyeoo-profile close`（学科网用 zxxk-profile）关闭。
- **严禁 `close --all`**（会误杀持久化会话配置，正是此前登录态反复丢失、失败率高的根因）。
- 说明：登录态存于本地 profile，未做任何跨设备持久化/上传。

### 第 2 级：通用搜索（WebSearch）
> **通道说明**：Step 3.0 用户选 **WebSearch** 时，本级即本次的**正式检索通道**（不属降级，也不启浏览器/不登录）；用户选站点通道时，本级仅作站内检索结果的补充，不可替代。
- 用上面模板的检索词做 WebSearch，优先命中：公开题库、教研论坛、百度文库、知乎、微信公众号文章、政府/学校公开试卷。
- **实测有效的命中源**：21世纪教育网 zy.21cnjy.com（一轮/专题讲义，含完整例题解析）、同桌100 tongzhuo100.com（课堂讲义与作业）、ima.qq.com 知识库分享页。检索词带"讲义 / 一轮复习 / 课堂作业 / 典例分析"更易命中完整题。
- 收集 3~5 道**相似题摘要**（题干要点 + 来源链接 + 知识点标注），作为改写素材库。
- 若搜索结果稀少或质量低 → 进入第 3 级。

### 第 3 级：模型内置经典题库（回退）
- 基于模型自身对「该知识点 + 该方法」经典题与常见变式的掌握，生成 2~3 道素材题。
- **必须显式标注**：「来源：模型知识库，未联网核验，建议人工核对出处与正确性」。
- 该级仅作兜底，不能替代前两级；若前两级有结果，优先使用前两级。

### 失败降级与超时（硬规则，实测沉淀）
- **检索脚本必须带总时限（2026-10-16 实测坑）**：自研 CDP/WS 客户端或浏览器自动化都可能卡死（如 Runtime.evaluate 永不返回）。任何检索脚本外层必须设总超时（建议单次 ≤90s），超时即按"失败 1 次"计数走降级路径，禁止无限等待。
- **检索失败降级路径（2026-10-16）**：连续 2 次检索尝试失败后，向用户说明并降级到第 2 级 WebSearch 取相似题源；若此前同母题的目标站点站内检索结果仍有缓存（如 `/tmp/jyeoo_results*.json` 或 `/tmp/zxxk_results*.json`），可作为有效母源库一并使用，溯源节如实注明"本次站内检索未成功，采用 X 日缓存 + Web 检索核验"。
- **登录失败降级路径（实测经验，2026-10-13）**：题库站点登录态易过期；二维码有效期极短易失效；从本机 Chrome 带 `--remote-debugging-port` 导出 cookie 注入 profile 后服务端仍不认（会话与 cookie 之外另有服务端绑定）——**不要在这条路上反复消耗**。连续 2 次登录尝试失败后，向用户说明并降级到第 2 级 WebSearch 取相似题源，溯源节如实注明"题库站点站内检索因登录失效未执行，改用 Web 检索"，并建议用户人工核验来源。

## 三、素材库整理要求
对每道收集到的相似题，记录：
- 知识点 / 方法（是否与原题一致）
- 题干核心结构（已知→所求）
- 来源（站点名 + 链接，或"模型知识库"）
- 可作为改编的切入点（数据/情境/图形/设问）

## 四、一致性红线（检索阶段也要守）
- 只采用**知识点或方法与原题一致**的题作为素材；明显不同知识点/方法的题，即便"长得像"也排除。
- 若三级回退后仍找不到合适素材，向用户说明，并基于原题本身做"保守变形"（换数字/换情境），仍保证方法一致。

## 五、注意事项
- 不要臆造不存在的 URL 或声称"已抓取某站内部题"。
- 涉及版权内容，只摘录题干要点与知识点，**不整段搬运原题原文**；改编生成的内容须为原创表达。
- 联网失败属于正常情况，按回退策略处理即可，无需向用户报错。
